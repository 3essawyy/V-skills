Rules:
1. Header: `# {TITLE}`, then `### <subtitle: one line saying what this lecture covers, from its slide titles>`, then a blank line and
   `> **Source:** \`{PDF}\` ({N} slides) · <instructor, course, part, date facts from the title slide, as written there>`
   `> **Conversion note:** slide text is the instructor's; blocks marked "AI transcription" or "AI-added" are AI-written — check the linked image / the PDF for exact details.`
2. Drop slides that teach nothing: the title slide (its facts go in the Source line), course-outline/agenda slides, section-divider slides whose only content is a section name (reuse the name as a PART or subsection title), thank-you / acknowledgment / references-only slides. Never drop a slide with any teaching content (definitions, examples, figures with information). List every dropped slide in the footer (rule 11).
3. Structure: group the kept slides into 3-7 PARTs, and each PART into subsections of consecutive slides on one sub-topic (usually 1-4 slides; a long run of slides with the same title is split where the content shifts).
   - PART: `<a id="part-N"></a>` + `## PART N — <topic>`.
   - Subsection: `<a id="part-N-M"></a>` + `### N.M <subtopic> (slides a–b)` or `(slide a)`. The title says what the slides cover (not just "Example").
   - Every kept slide: a hidden anchor `<a id="sNN"></a>` (2-digit slide number) on its own line before that slide's content, in slide order. No per-slide headings.
4. Table of Contents after the header: `## Table of Contents`, each PART `- [PART N — topic](#part-N) *(slides a–b)*` with its subsections nested `  - [N.M subtopic](#part-N-M) *(slides a–b)*`. Every link must resolve. Then `### Roadmap (AI-added)` with ONE small Mermaid `flowchart LR` of how the PARTs lead into each other (one node per PART, optionally a key subsection), built only from PART/subsection titles, safe subset + classDefs (rule 9).
5. Slide text: keep wording verbatim. Fix layout only: `-` bullets (2-space nesting), re-join lines broken mid-sentence, fix obvious PDF artifacts. Delete: a line repeating the slide/subsection title, footer lines repeated across slides (date, instructor name, course name, slide numbers), scrambled equation fragments (jumbled single words) when the figure gives the formula. Within one subsection, a text line identical to one already written there is written once (progressive builds); every figure of every build is still kept, in order.
6. Make it look good without adding words (style guide tables/formatting/math sections):
   - Tables: >=2 items compared on >=2 shared attributes → comparison table; >=3 structured records or >=3 "label: explanation" pairs → table; a formula followed by symbol definitions → `Symbol | Meaning` table under it. Same words as the slide. HTML `<table>` only for merged cells. Legends/footnotes → `> **Notes & Footnotes**` blockquote under the table.
   - Bold the term in a line where the slide defines it. A line the slide labels "Note:", "Important:", "Remember:" may be wrapped in `> [!IMPORTANT]` / `> [!NOTE]` with its exact words.
   - Math: formulas with fractions, sub/superscripts, Greek, sums → LaTeX (`$...$` inline, `$$...$$` own lines at top level; inside blockquotes/lists use a ```math fence). Escape literal `\$`. No bare `|` in table math. Formal notation that isn't arithmetic (grammars, regexes, code, commands) → `code`; escape `\|` in tables.
   - Code fences always name a language (`text` if none fits).
7. Key Idea callout (optional, max ONE per PART): directly under the `## PART` heading, before its first subsection anchor: `> [!TIP]` newline `> **Key Idea (AI-added):** <1-2 sentences, <=60 words>`, restating only what that PART's slides say. Skip it when there is no single clear takeaway.

Figures marked `skip` and `<!-- skipped decorative ... -->` lines are dropped. A figure block starting with `drop:` marks a slide to drop (rule 2): use its text for the Source line (title slide) or as the PART/subsection title (section divider), then drop the slide.
